A message queue lets you say "I'll do that in the background, here's your response now."

Producer -> The thing that creates tasks (your API route)
Queue -> Where tasks wait to be processed (Redis or Kafka)
Consumer/Worker -> The thing that picks up and processes tasks
Broker -> The middleman managing the queue (Redis in this case)

Celery is Python's most popular task queue library. It uses Redis as its broker:

Needs 2 things:

#1: broker=the queue

FastAPI
   |
   | "send notification"
   ↓
 Redis Queue
   |
   ↓
 Celery Worker
   |
   ↓
 send email

#2: backend=stores the task result

Task started
      |
      ↓
Celery Worker
      |
      ↓
"Notification sent"
      |
      ↓
Redis stores result

@celery_app.task -> “This function is not a normal Python function. Register it as a background job.” can use .delay()

command: celery -A tasks.celery_app worker --loglevel=info

- general format: celery -A <python_file>.<celery_variable>

- A tasks.celery_app - “Find my Celery application inside this Python file.”

- "worker" -> Starts a Celery worker process. The worker is the thing that actually executes your background jobs.

- --loglevel=info -> Controls how much logging Celery prints. Can also replace info with debug,warning,etc
